### 2.4 execute 内部逻辑

**偏移**：+223 ～ +334

```
偏移 +232: if (signal?.aborted) → reject("Operation aborted")

偏移 +245: absolutePath = await resolveReadPathAsync(path, cwd)
偏移 +248: await ops.access(absolutePath)  ← 检查可读
偏移 +250: mimeType = ops.detectImageMimeType ? await ops.detectImageMimeType(absolutePath) : undefined

if (mimeType):
  偏移 +256: buffer = await ops.readFile(absolutePath)
  偏移 +257: processed = await processImage(buffer, mimeType, { autoResizeImages })
  → 如果 !processed.ok → content = [{ type: "text", text: errorNote }]
  → 如果 processed.ok → content = [{ type: "text", text: note }, { type: "image", data, mimeType }]

else (text file):
  偏移 +273: buffer = await ops.readFile(absolutePath)
  偏移 +274: textContent = buffer.toString("utf-8")
  偏移 +275: allLines = textContent.split("\n")
  偏移 +277: startLine = offset ? Math.max(0, offset - 1) : 0  ← 转为 0-indexed

  if (limit !== undefined):
    偏移 +288: endLine = Math.min(startLine + limit, allLines.length)
    selectedContent = allLines.slice(startLine, endLine).join("\n")

  else:
    偏移 +292: selectedContent = allLines.slice(startLine).join("\n")

  偏移 +295: truncation = truncateHead(selectedContent)  ← 截断

  if (truncation.firstLineExceedsLimit):
    → 返回 bash fallback 提示

  if (truncation.truncated):
    → 返回截断内容 + 续读提示 "Use offset=X to continue."

  if (userLimitedLines && more content):
    → 返回内容 + 续读提示

  else:
    → 返回完整内容

偏移 +327: resolve({ content, details })
```

### 3.2 execute 内部逻辑

```
文件：packages/coding-agent/src/core/tools/bash.ts
函数：createBashToolDefinition 的 execute
```

关键步骤：
1. `resolveTimeoutMs(timeout)` — 校验并转换超时
2. `getShellConfig(cwd, signal)` — 获取 shell 配置（检测可用 shell）
3. `getShellEnv(cwd, shellConfig)` — 获取 shell 环境
4. `spawn(command, { shell, cwd, env, ... })` — 启动子进程
5. `OutputAccumulator` — 累积 stdout/stderr
6. `waitForChildProcess(child, timeoutMs, signal)` — 等待完成
7. 截断输出（`truncateHead` for stdout, `truncateTail` for stderr）
8. 返回 `{ content: [{ type: "text", text: output }], details: { truncation, fullOutputPath } }`

### 3.3 关键设计

- `killProcessTree` — 中断时杀掉整个进程树（包括子进程）
- `trackDetachedChildPid`/`untrackDetachedChildPid` — 跟踪后台进程
- `OutputAccumulator` — 流式收集输出，避免内存溢出
- 超时和 abort 都通过 signal 处理

### 4.2 execute 内部逻辑

关键步骤：
1. `resolveToCwd(path, cwd)` — 解析路径

7. 返回 `{ content: [{ type: "text", text: "Edited N lines" }], details: { changes } }`

## 6. 工具注册流程

### 6.1 _buildRuntime

```
文件：packages/coding-agent/src/core/agent-session.ts
方法：AgentSession._buildRuntime
```

执行内容：
1. 调用 `createAllToolDefinitions(cwd, options)` — 创建所有工具定义
2. 将每个 `ToolDefinition` 注册到 `_toolDefinitions` Map
3. 通过 `wrapToolDefinition` 转为 `AgentTool`
4. 注册到 `_toolRegistry` Map
5. 根据 `_initialActiveToolNames`、`_allowedToolNames`、`_excludedToolNames` 过滤
6. 设置 `this.agent.state.tools` 为激活的工具列表

## 7. 工具执行流程图

```
LLM 返回 AssistantMessage { content: [{ type: "toolCall", name, arguments }] }
  │
  ▼
executeToolCalls → executeToolCallsParallel/Sequential
  │
  for each toolCall:
  ├── emit("tool_execution_start")
  │
  ├── prepareToolCall:
  │   ├── find tool in context.tools by name
  │   ├── prepareToolCallArguments (可选)
  │   ├── validateToolArguments (TypeBox schema)
  │   └── beforeToolCall hook (扩展)
  │       └── extensionRunner.emitToolCall({ toolName, input })
  │
  ├── executePreparedToolCall:
  │   └── tool.execute(toolCallId, args, signal, onUpdate)
  │       │
  │       ├── [read]: resolveReadPathAsync → access → readFile → truncate
  │       ├── [bash]: spawn → waitForChildProcess → truncate
  │       ├── [edit]: readFile → find/replace → writeFile
  │       └── [write]: mkdir → writeFile
  │       │
  │       └── onUpdate(partialResult) → emit("tool_execution_update")
  │
  ├── finalizeExecutedToolCall:
  │   └── afterToolCall hook (扩展)
  │       └── extensionRunner.emitToolResult({ content, details, isError })
  │       └── normalizeToolResultImages
  │
  ├── emit("tool_execution_end")
  │
  └── createToolResultMessage:
      → { role: "toolResult", toolCallId, toolName, content, details, isError, timestamp }
```

## 8. 工具错误处理

| 错误来源 | 处理 | 返回给 LLM |
|---------|------|-----------|
| 工具未找到 | `prepareToolCall` → `ImmediateToolCallOutcome` | `"Tool {name} not found"` |
| 参数校验失败 | `prepareToolCall` catch → `ImmediateToolCallOutcome` | 错误消息 |
| beforeToolCall 阻止 | `prepareToolCall` → `ImmediateToolCallOutcome` | `reason` 或默认消息 |
| execute 抛异常 | `executePreparedToolCall` catch → errorResult | 异常消息 |
| 文件不存在 | `ops.access` 抛异常 → execute catch | `"ENOENT: no such file..."` |
| 命令超时 | `waitForChildProcess` → kill → error | `"Command timed out"` |
| 被中断 | `signal.aborted` → reject | `"Operation aborted"` |

## 9. Pluggable Operations 设计

所有工具都支持 `operations` 选项，允许覆盖文件系统操作：

```typescript
// 默认使用本地文件系统
const defaultReadOperations: ReadOperations = {
  readFile: (path) => fsReadFile(path),
  access: (path) => fsAccess(path, constants.R_OK),
  detectImageMimeType: detectSupportedImageMimeTypeFromFile,
};

// 可覆盖为远程操作（如 SSH）
const remoteReadOps: ReadOperations = {
  readFile: (path) => sshReadFile(path),
  access: (path) => sshCheckReadable(path),
  // detectImageMimeType: 可选
};
```

**设计意图**：支持 SSH 远程代理（Gondolin 扩展）和容器化场景，工具逻辑不变，只替换底层 IO。
