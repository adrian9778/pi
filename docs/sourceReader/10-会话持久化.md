## 1. 存储格式：JSONL 追加树

### 1.1 文件结构

每个会话是一个 `.jsonl` 文件，每行一个 JSON 对象，第一行是 SessionHeader：

```
{"type":"session","version":3,"id":"01923a...","timestamp":"2026-08-31T...","cwd":"/Users/vincent/...","parentSession":null}
{"type":"message","id":"a1b2c3d4","parentId":null,"timestamp":"...","message":{"role":"user","content":"read config.json",...}}
{"type":"message","id":"e5f6a7b8","parentId":"a1b2c3d4","timestamp":"...","message":{"role":"assistant","content":[...],...}}
{"type":"message","id":"c9d0e1f2","parentId":"e5f6a7b8","timestamp":"...","message":{"role":"toolResult",...}}
...
```

### 1.2 树结构

每个 `SessionEntry` 有 `id` + `parentId`，形成从根到叶的路径：

```
root (parentId=null)
  └── entry1 (parentId=null → root)
        └── entry2 (parentId=entry1)
              └── entry3 (parentId=entry2)  ← leafId
```

**关键设计**：分支不修改历史。`branch(fromId)` 只移动 `leafId` 指针，下次 `append` 创建 `fromId` 的子节点，自然形成新分支。

### 3.3 _persist() — 延迟写入策略

```
session-manager.ts → SessionManager._persist
偏移：+1016
```

**关键设计**：文件在第一条助手消息到达时才创建。

```typescript
_persist(entry: SessionEntry): void {
  if (!this.persist || !this.sessionFile) return;

  const hasAssistant = this.fileEntries.some(
    (e) => e.type === "message" && e.message.role === "assistant"
  );

  if (!hasAssistant) {
    // 还没有助手消息：不写文件（避免空会话文件）
    this.flushed = false;
    return;
  }

  if (!this.flushed) {
    // 首次写：创建文件 + 写入所有积攒的条目
    const fd = openSync(this.sessionFile, "wx"); // 独占创建
    for (const e of this.fileEntries) {
      writeFileSync(fd, `${JSON.stringify(e)}\n`);
    }
    this.flushed = true;
  } else {
    // 后续写：只追加新条目
    appendFileSync(this.sessionFile, `${JSON.stringify(entry)}\n`);
  }
}
```

**为什么延迟到助手消息？**：避免创建只有用户消息的空壳文件——用户输入后中断或模型失败时不留下碎片会话。

### 4.1 buildSessionPath()

```
session-manager.ts → function buildSessionPath
```

```typescript
function buildSessionPath(entries, leafId?, byId?): SessionEntry[] {
  const index = buildEntryIndex(entries, byId);
  let leaf: SessionEntry | undefined;
  if (leafId === null) return [];           // resetLeaf 状态
  if (leafId) leaf = index.get(leafId);
  leaf ??= entries[entries.length - 1];    // 默认最后一条

  const path: SessionEntry[] = [];
  let current = leaf;
  while (current) {
    path.push(current);
    current = current.parentId ? index.get(current.parentId) : undefined;
  }
  path.reverse();
  return path;
}
```

从叶到根回溯，然后反转得到根到叶路径。

### 4.2 buildContextEntries() — 压缩感知

```typescript
function findMostRecentSession(sessionDir: string, cwd?: string): string | null {
  const files = readdirSync(sessionDir)
    .filter(f => f.endsWith(".jsonl"))
    .map(path => ({ path, header: readSessionHeaderForDiscovery(path) }))
    .filter(file => file.header && (!cwd || sessionCwdMatches(...)))
    .map(({ path }) => ({ path, mtime: statSync(path).mtime }))

}
```

## 11. 关键设计决策

1. **追加-only**：文件只追加不修改——崩溃时已有数据安全。`createBranchedSession` 和版本迁移是仅有的全量重写场景。

2. **延迟创建**：文件在第一条助手消息到达时才创建。用户只输入未得到响应的会话不留下碎片文件。

3. **树而非线性数组**：v2 引入 `id/parentId` 树结构，使分支无需复制——移动 `leafId` 即可，历史条目共享。

4. **压缩感知**：`buildContextEntries` 自动处理压缩——摘要条目替代旧消息，`firstKeptEntryId` 标记保留起点。

5. **Header 快速扫描**：`readSessionHeader` 只读 4KB 缓冲，列表发现时不加载整个文件。1MB 上限防止恶意/损坏文件。

6. **同步文件 I/O**：`loadEntriesFromFile` 和 `_persist` 使用同步 fs API。原因：会话写入在 Agent 事件循环中，需要确定性的写入顺序；异步 I/O 可能导致事件交叉。

7. **generateId 8-hex**：8 字符十六进制（4 字节随机），在 `byId` Set 中碰撞检查。足够 16M 条目碰撞概率极低，且 100 次重试后 fallback 到完整 UUID。

8. **convertToLlm 边界**：自定义消息类型（bashExecution、compactionSummary 等）在 LLM 调用边界统一转换为标准 `Message`——Agent 内部使用丰富的 `AgentMessage`，向外只呈现 LLM 兼容格式。
