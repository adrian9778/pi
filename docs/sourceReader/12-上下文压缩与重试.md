### 3.3 上下文 Token 估算

```
compaction.ts → function estimateContextTokens
偏移：+202
```

**策略**：优先使用最后一次 assistant 消息的 usage，再加上其后消息的估算。

```typescript
function estimateContextTokens(messages: AgentMessage[]): ContextUsageEstimate {
  const usageInfo = getLastAssistantUsageInfo(messages);

  if (!usageInfo) {
    // 无 usage：全部消息用 estimateTokens 估算
    let estimated = 0;
    for (const message of messages) estimated += estimateTokens(message);
    return { tokens: estimated, usageTokens: 0, trailingTokens: estimated, lastUsageIndex: null };
  }

  const usageTokens = calculateContextTokens(usageInfo.usage);
  let trailingTokens = 0;
  for (let i = usageInfo.index + 1; i < messages.length; i++) {
    trailingTokens += estimateTokens(messages[i]);
  }
  return { tokens: usageTokens + trailingTokens, usageTokens, trailingTokens, lastUsageIndex: usageInfo.index };
}
```

**为什么这样设计**：
- 模型返回的 usage 是截至该消息的完整上下文 token 数（包含 system prompt + 所有历史 + 当前消息）
- 其后的消息没有 usage，只能估算
- 两者相加 = 当前上下文总量

```
偏移：+235
```

```typescript
function shouldCompact(contextTokens: number, contextWindow: number, settings: CompactionSettings): boolean {
  if (!settings.enabled) return false;
  return contextTokens > contextWindow - settings.reserveTokens;
}
```

当 `contextTokens + reserveTokens > contextWindow` 时触发——即在窗口溢出之前预留 `reserveTokens`（16K）的空间来生成摘要。

```
触发条件: contextTokens > contextWindow - reserveTokens

例: contextWindow = 200000, reserveTokens = 16384
    触发阈值 = 200000 - 16384 = 183616
    当 contextTokens > 183616 → 压缩
```

### 5.3 查找切点

```
compaction.ts → function findCutPoint
偏移：+403
```

**算法**：从最新消息向回走，累积 token，直到达到 `keepRecentTokens` 预算。

```
输入: entries[], startIndex, endIndex, keepRecentTokens

1. findValidCutPoints(entries, startIndex, endIndex) → cutPoints[]

2. 向回遍历 (i = endIndex-1 → startIndex):
   accumulatedTokens += estimateTokens(entries[i])
   if accumulatedTokens >= keepRecentTokens:
     找到 >= i 的最近 cutPoint → cutIndex
     break

3. 向回扫描 cutIndex 之前的无关 entry（metadata-only）:
   while entries[cutIndex-1] 不是 compaction 且不产生上下文消息:
     cutIndex--

4. 判断是否为"分裂轮次":
   isSplitTurn = !isTurnStartEntry(cutEntry) && findTurnStartIndex(...) != -1

5. 返回 CutPointResult:
   { firstKeptEntryIndex, turnStartIndex, isSplitTurn }
```

**分裂轮次的含义**：切点落在一个轮次的中间（assistant 消息处），而非轮次开始处。此时需要额外处理——将该轮次的前半部分也进行摘要。

```typescript
function computeFileLists(fileOps: FileOperations): { readFiles: string[]; modifiedFiles: string[] } {
  const modified = new Set([...fileOps.edited, ...fileOps.written]);
  const readOnly = [...fileOps.read].filter((f) => !modified.has(f)).sort();
  const modifiedFiles = [...modified].sort();
  return { readFiles: readOnly, modifiedFiles };
}
```

- `readFiles` = 只读未改的（排除被修改的文件）

```

   ├── 有 previousSummary → UPDATE_SUMMARIZATION_PROMPT

5. 构建 promptText:

8. 验证响应:
```

## 10. 重试机制

### 10.1 可重试错误分类

```

```

**两阶段判定**：

```
阶段 1: 检查 NON_RETRYABLE（不可重试）模式
  匹配 → return false（不可重试）

阶段 2: 检查 RETRYABLE（可重试）模式
  匹配 → return true（可重试）

```

**NON_RETRYABLE 模式**（不重试）：

| 模式 | 含义 |
|------|------|
| `quota` / `rate_limit_exceeded` | 配额/速率限制 |
| `billing` / `insufficient_quota` | 账单问题 |
| `authentication` / `invalid_api_key` | 认证失败 |
| `permission` / `forbidden` | 权限不足 |
| `content_filter` / `content_policy` | 内容违规 |
| `model_not_found` | 模型不存在 |

**RETRYABLE 模式**（可重试）：

| 模式 | 含义 |
|------|------|
| `429` / `rate_limit` | HTTP 429 限流（短暂） |
| `500` / `502` / `503` / `504` | 5xx 服务器错误 |
| `overloaded` | 服务过载 |
| `internal_error` / `server_error` | 内部错误 |
| `connection` / `network` / `timeout` | 网络问题 |
| `stream` / `terminated` / `aborted` | 流中断 |
| `websocket` / `socket` | 连接断开 |
| `temporary` / `unavailable` | 临时不可用 |

### 10.2 重试执行

```
pi-ai/utils/retry.ts → function retryAssistantCall
偏移：+163
```

```typescript
async function retryAssistantCall<T>(
  produce: () => Promise<T>,
  retry?: RetryPolicy,
  signal?: AbortSignal,
  callbacks?: RetryCallbacks,
): Promise<T>
```

**算法**：

```
for attempt = 1 to maxRetries+1:
  try:
    (callbacks.onRetryAttemptStart)
    result = await produce()
    (callbacks.onRetryFinished)
    return result

  catch error:
    if signal?.aborted → throw (中断立即退出)
    if !isRetryableAssistantError(error) → throw (不可重试立即退出)
    if attempt > maxRetries → throw (超过最大重试次数)

    delay = baseDelayMs * 2^(attempt-1)   // 指数退避
    (callbacks.onRetryScheduled)
    await sleep(delay, signal)             // 可被 abort 中断的 sleep
```

**指数退避示例**（`baseDelayMs = 1000`）：

| 重试次数 | 延迟 |
|---------|------|
| 1 | 1000ms (1s) |
| 2 | 2000ms (2s) |
| 3 | 4000ms (4s) |
| 4 | 8000ms (8s) |
| 5 | 16000ms (16s) |

### 10.4 可中断 Sleep

```
pi-ai/utils/retry.ts → function sleep
偏移：+127
```

```typescript
function sleep(ms: number, signal?: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(new RetrySleepAbortError());
    const timer = setTimeout(() => {
      signal?.removeEventListener("abort", onAbort);
      resolve();
    }, ms);
    const onAbort = () => { clearTimeout(timer); reject(new RetrySleepAbortError()); };
    signal?.addEventListener("abort", onAbort, { once: true });
  });
}
```

当用户中断时，`signal.aborted` 变为 true，sleep 立即 reject `RetrySleepAbortError`，重试循环中捕获后直接 throw（不重试）。

```
用户发送第 N 条消息 → Agent 完成 → AgentSession 检查压缩

┌─────────────────────────────────────────────────────────────────┐
│ Step 1: 估算上下文                                              │
│                                                                 │
│   entries = session.buildContextEntries()                       │
│   messages = sessionEntryToContextMessages(entries)             │
│   estimate = estimateContextTokens(messages)                    │
│   contextTokens = estimate.tokens                               │
│                                                                 │
│   shouldCompact(contextTokens, contextWindow, settings)?       │
│   → false: 继续                                                │
│   → true: 进入 Step 2                                          │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 2: 准备压缩                                               │
│                                                                 │
│   pathEntries = session.buildPathEntries()                      │
│   preparation = prepareCompaction(pathEntries, settings)       │
│                                                                 │
│   内部:                                                         │
│   ├── 查找 prevCompactionIndex                                  │
│   ├── 确定 boundaryStart (上次压缩的保留起点)                    │
│   ├── estimateContextTokens → tokensBefore                     │
│   ├── findCutPoint → CutPointResult                             │
│   ├── 提取 messagesToSummarize                                 │
│   ├── (if split) 提取 turnPrefixMessages                       │
│   └── extractFileOperations → fileOps                          │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 3: 生成摘要                                               │
│                                                                 │
│   compact(preparation, model, apiKey, headers, ...)            │
│                                                                 │
│   内部:                                                         │
│   ├── (if split)                                               │
│   │   ├── generateSummaryWithUsage(messagesToSummarize)        │
│   │   │   ├── convertToLlm → serializeConversation             │
│   │   │   ├── buildSummarizationContext                         │
│   │   │   └── completeSummarization                             │
│   │   │       └── retryAssistantCall                           │
│   │   │           └── streamFn(model, context, opts)          │
│   │   └── generateTurnPrefixSummary(turnPrefixMessages)        │
│   └── (if not split)                                           │
│       └── generateSummaryWithUsage(messagesToSummarize)        │
│   ├── computeFileLists → formatFileOperations                  │
│   └── 返回 CompactionResult                                     │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│ Step 4: 持久化                                                  │
│                                                                 │
│   session.appendCompaction(CompactionResult)                    │
│   → 追加 CompactionEntry 到 JSONL                               │
│     { type: "compaction",                                       │
│       summary: "...",                                           │
│       firstKeptEntryId: "uuid...",                              │
│       details: { readFiles: [...], modifiedFiles: [...] },     │
│       id, parentId, timestamp }                                │
│                                                                 │
│   下次 buildContextEntries 时:                                   │
│   ├── 从 leafId 回溯到根                                        │
│   ├── 遇到 CompactionEntry → 截断                               │
│   │   (只保留 firstKeptEntryId 之后的路径 + 摘要)               │
│   └── CompactionSummaryMessage 作为路径中的第一个消息           │
└─────────────────────────────────────────────────────────────────┘
```

## 12. 迭代压缩设计

压缩系统支持**迭代更新**——每次压缩不是从头生成摘要，而是在上次摘要基础上增量更新：

```
第 1 次压缩:
  messagesToSummarize = [msg1...msg50] (前 50 条)
  previousSummary = undefined
  → 使用 SUMMARIZATION_PROMPT (初始)
  → summary_v1

第 2 次压缩:
  messagesToSummarize = [msg51...msg80] (msg50 之后的 30 条)
  previousSummary = summary_v1
  → 使用 UPDATE_SUMMARIZATION_PROMPT (更新)
  → summary_v2 (合并了 v1 旧信息 + 新进展)

第 3 次压缩:
  messagesToSummarize = [msg81...msg110]
  previousSummary = summary_v2
  → UPDATE_SUMMARIZATION_PROMPT
  → summary_v3
```

**优势**：每次压缩只处理新增消息，而非全部历史。摘要保持结构化格式，随会话演进逐步更新。
