## 2. Print 模式

```
print-mode.ts → function runPrintMode
偏移：+33
```

### 2.1 参数

```typescript
interface PrintModeOptions {
  mode: "text" | "json";           // 输出模式
  messages?: string[];             // 额外消息
  initialMessage?: string;         // 首条消息（可含 @file）
  initialImages?: ImageContent[];  // 附加图片
}
```

### 2.2 执行流程

```
1. 注册信号处理 (SIGTERM, SIGHUP)
   → 收到信号: killTrackedDetachedChildren → disposeRuntime → exit

2. rebindSession()
   ├── session.bindExtensions({ mode: "json"|"print", ... })
   ├── session.subscribe((event) => {
   │     if (mode === "json") writeRawStdout(JSON.stringify(toJsonEvent(event)) + "\n")
   │   })
   └── (json only) session.agent.subscribe(backpressure handler)

3. (json only) 输出 session header
   writeRawStdout(JSON.stringify(session.sessionManager.getHeader()) + "\n")

4. 发送消息
   ├── initialMessage → session.prompt(initialMessage, { images })
   └── messages[] → for each: session.prompt(message)

5. (text only) 提取最终回复
   lastMessage = state.messages[last]
   if assistant:
     ├── stopReason == "error" | "aborted" → stderr, exitCode=1
     └── else → for each text content block: writeRawStdout(text + "\n")

6. 清理
   ├── 移除信号处理
   ├── disposeRuntime()
   └── flushRawStdout()
```

### 2.3 关键设计

**text vs json 的区别**：
- `text`：只输出最终助手回复的文本内容，不输出中间事件
- `json`：所有 AgentSession 事件都序列化为 JSON 行输出到 stdout

**信号处理**：SIGTERM/SIGHUP 触发优雅关闭——先杀分离子进程，再释放运行时。

**rebindSession 的作用**：当会话切换（new_session/fork/switch_session）时，需要重新绑定事件订阅和扩展。`runtimeHost.setRebindSession` 注册了重绑回调。

### 3.1 事件转换

将内部 `AgentSessionEvent` 转换为 JSON 协议兼容的 `JsonAgentSessionEvent`。

**核心处理**：移除 `message_update` 事件中的累积快照（`partial` 字段）。

```
json-event.ts → function toJsonAssistantMessageEvent
偏移：+20
```

```typescript
function toJsonAssistantMessageEvent(event): JsonMessageUpdateEvent["assistantMessageEvent"] {
  if (event.type === "toolcall_start") {
    // 提取 toolCall.id 和 toolCall.name，移除 partial
    const toolCall = event.partial.content[event.contentIndex];
    const { partial: _partial, ...deltaEvent } = event;
    return { ...deltaEvent, id: toolCall.id, toolName: toolCall.name };
  }
  if (!("partial" in event)) return event;
  const { partial: _partial, ...deltaEvent } = event;
  return deltaEvent;
}
```

**为什么移除 partial**：
- `message_start` 提供初始消息，增量 delta 构建它，`message_end` 提供最终权威消息
- 累积快照体积大且冗余（每次 delta 都包含完整累积状态）
- 保留 usage（体积固定）、toolCall id/name（体积固定）

### 3.2 类型设计

```typescript
type ToJsonAssistantMessageEvent<T> = T extends { type: "toolcall_start"; partial: unknown }
  ? WithoutPartial<T> & { id: string; toolName: string }
  : WithoutPartial<T>;
```

`WithoutPartial<T>` 使用条件类型移除 `partial` 字段。`toolcall_start` 额外添加 `id` 和 `toolName`。

### 4.2 输出接管

```
output-guard.ts → function takeOverStdout
偏移：+45
```

RPC 模式调用 `takeOverStdout()` 接管 stdout：
- **原始 stdout.write** 被保存为 `rawStdoutWrite`（用于输出 JSON 事件）
- **process.stdout.write** 被替换为重定向到 **stderr** 的函数
- 这样，扩展/库代码中的 `console.log` / `process.stdout.write` 不会污染 JSON 协议流

```
output-guard.ts → function writeRawStdout
偏移：+85
```

```typescript
function writeRawStdout(text: string): void {
  if (text.length === 0) return;
  rawStdoutWriteTail = rawStdoutWriteTail.then(() => writeRawStdoutChunk(text));
  void rawStdoutWriteTail.catch(() => process.exit(1));
}
```

- 串行化写入：`rawStdoutWriteTail` Promise 链保证所有写入按顺序执行
- 错误退出：写入失败立即 `process.exit(1)`

```
output-guard.ts → function writeRawStdoutChunk
偏移：+20
```

处理 `ENOBUFS` / `EAGAIN` / `EWOULDBLOCK` 错误——当 stdout 缓冲区满时，等待 10ms 后重试。

```
output-guard.ts → function waitForRawStdoutBackpressure
偏移：+95
```

等待所有待写入完成。用于背压控制——当输出队列太长时暂停生产。

### 4.3 JSONL 行读取器

```
rpc/jsonl.ts → function attachJsonlLineReader
偏移：+21
```

**为什么不用 Node.js readline**：readline 会在额外的 Unicode 分隔符（U+2028, U+2029）上分割，而这些在 JSON 字符串中是合法字符。JSONL 要求仅在 `\n` 上分割。

**实现**：
- `StringDecoder` 处理多字节 UTF-8 边界
- 手动缓冲区 + `indexOf("\n")` 分割
- `\r` 后缀自动去除（兼容 Windows 换行）
- 返回 detach 函数（移除 data/end 监听器）

```
rpc/jsonl.ts → function serializeJsonLine
偏移：+10
```

```typescript
function serializeJsonLine(value: unknown): string {
  return `${JSON.stringify(value)}\n`;
}
```

LF-only 分帧。JSON 字符串内的 U+2028/U+2029 由 `JSON.stringify` 转义为 `\u2028`/`\u2029`，不影响分帧。

**prompt 命令的特殊处理**（偏移 +394）：

```typescript
case "prompt": {
  let preflightSucceeded = false;
  void session.prompt(command.message, {
    images: command.images,
    streamingBehavior: command.streamingBehavior,
    source: "rpc",
    preflightResult: (didSucceed) => {
      if (didSucceed) {
        preflightSucceeded = true;
        output(success(id, "prompt"));  // 成功时才发 response
      }
    },
  }).catch((e) => {
    if (!preflightSucceeded) {
      output(error(id, "prompt", e.message));
    }
  });
  return undefined;  // 异步：response 在 preflight 后发送，事件流跟随
}
```

**设计**：prompt 命令是异步的——先发送 response（表示命令已接受），后续通过事件流传输对话内容。

阻塞式 UI 请求的实现：

```typescript
function createDialogPromise<T>(opts, defaultValue, request, parseResponse): Promise<T> {
  if (opts?.signal?.aborted) return Promise.resolve(defaultValue);

  const id = crypto.randomUUID();
  return new Promise((resolve, reject) => {
    // 超时处理
    if (opts?.timeout) {
      timeoutId = setTimeout(() => { cleanup(); resolve(defaultValue); }, opts.timeout);
    }
    // abort 信号
    opts?.signal?.addEventListener("abort", onAbort, { once: true });
    // 注册到 pendingExtensionRequests Map
    pendingExtensionRequests.set(id, { resolve, reject });
    // 发送 UI 请求到 stdout
    output({ type: "extension_ui_request", id, ...request });
  });
}
```

当客户端发回 `extension_ui_response` 时：

// handleInputLine 中
if (parsed.type === "extension_ui_response") {

  if (pending) {
    pendingExtensionRequests.delete(response.id);
    pending.resolve(response);  // 解除阻塞
  }
  return;
}

### 4.6 关闭机制

```
rpc-mode.ts → function shutdown (闭包)
偏移：+728
```

```typescript
async function shutdown(exitCode = 0, signal?: NodeJS.Signals): Promise<never> {
  if (shuttingDown) process.exit(exitCode);
  shuttingDown = true;
  // 1. 移除信号处理
  for (const cleanup of signalCleanupHandlers) cleanup();
  // 2. 取消事件订阅
  unsubscribe?.();
  unsubscribeBackpressure?.();
  // 3. 释放运行时
  await runtimeHost.dispose();
  // 4. 断开 stdin
  detachInput();
  process.stdin.pause();
  // 5. 刷新 stdout（非 SIGTERM）
  if (signal !== "SIGTERM") await flushRawStdout();
  process.exit(exitCode);
}
```

**触发时机**：
- `shutdownRequested` 标志（由扩展设置 `shutdownHandler`）
- stdin end（客户端关闭输入流）
- 信号（SIGTERM/SIGHUP）

**agent_settled 后检查**：每轮对话结束后检查 `shutdownRequested`，实现"处理完当前请求再退出"的优雅关闭。

### 5.3 扩展 UI 上下文（TUI 版）

Interactive 模式实现了完整的 `ExtensionUIContext`：
- `select`/`confirm`/`input` → TUI overlay 对话框

- `notify` → toast 通知

- `setFooter`/`setHeader` → 自定义页眉页脚

### 5.4 键绑定系统

Interactive 模式通过 `KeybindingsManager` 管理键绑定：
- 全局键绑定（如 Ctrl+C 中断、Ctrl+L 清屏）

- 可通过 `settings.json` 自定义

## 6. AgentSessionRuntime — 模式共享基础

所有三种模式共享 `AgentSessionRuntime`，它封装了：
- `AgentSession` 实例（会话状态、消息列表、模型、思考级别）
- `ResourceLoader`（扩展、技能、主题、上下文文件）
- `ModelRuntime`（模型管理、认证）
- `ExtensionRunner`（扩展命令/工具/标志）

模式通过 `runtimeHost.session` 获取当前会话，通过 `runtimeHost.dispose()` 释放资源。

**会话切换**：
- `runtimeHost.newSession(options)` → 创建新会话
- `runtimeHost.fork(entryId, options)` → 从指定节点分支
- `runtimeHost.switchSession(path, options)` → 切换到已有会话
- `runtimeHost.setRebindSession(callback)` → 注册重绑回调
